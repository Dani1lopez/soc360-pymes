# QA Audit Report — soc360-pymes (2026-09-19)

Read-only integral audit. No code was modified, committed, or pushed. Method: three parallel read-only subagents (security review, configuration/infra audit, automated verification run) plus parent-level manual walkthroughs of the cross-tenant, auth, and assets contracts, a threat model, and a performance-pattern sweep. Every finding below cites a file/line and a reproducible check.

## Executive summary

| Severity | Count | Highlights |
| --- | --- | --- |
| HIGH | 5 | Hardcoded DB credentials in 5 tracked files; Docker image cannot boot (gunicorn absent from deps and config not copied); RLS possibly inert without `FORCE ROW LEVEL SECURITY` / correct owner-role split (deployment-dependent); CI lacks ruff/mypy/secret-scan gates while README claims them |
| MEDIUM | 13 | Tenant settings exposed to viewers; unauthenticated catalog probe; refresh-token reuse not detected; log redaction exact-match only; rate-limit pre-checks fail open on non-RedisError; gunicorn unconfigured; root container; migration hazards; stale docs |
| LOW | 12 | Unsalted email hashes, raw IPs in logs, inline test credentials, loose pins, no HEALTHCHECK, README drift |

Headline: the codebase's security craftsmanship is above average for its stage (JWT hardening, RLS policies, chokepoint logging, secret-key entropy validation, excellent concurrent-index migrations), but **three HIGH issues are real defects**: committed credentials, an unbootable production image, and an unverified RLS ownership invariant. The test suite also has **stale-test debt** from the Slice 1 column rename.

## Threat model (phase 2)

- Assets: user credentials, tenant PII, cross-tenant isolation, JWT/refresh secrets, LLM provider keys, scan results.
- Trust boundaries: Internet → API (HTTPS forced, CORS restricted, docs disabled in prod), app → Postgres (RLS), app → Redis (Streams/locks, password mandatory in prod), app → LLM providers, scraper → `/metrics` (rotating token, constant-time compare).
- Exposed surface: `/api/v1/{auth,tenants,users,assets}`, `/metrics`, `/health`, `/health/db/indexes` (unauthenticated).
- Verified guards: SECRET_KEY 128-char + entropy validators; mock-LLM-in-prod guard; CORS wildcard-with-credentials guard; Redis password required in prod; HS256-only JWT with DB-authoritative claims (token claims never trusted); bcrypt with timing equalization; refresh tokens stored hashed, single-use rotation, HttpOnly+Secure+SameSite=strict.

## Findings — triaged and prioritized

### P0 — fix immediately

**F1 · HIGH · Live DB credentials committed in tracked files** — `docker-compose.yml:31`, `openspec/changes/prd-v2-vertical-f2/apply-progress.md:67,174,228`, `tests/conftest.py:29`, `tests/integration/test_metrics_token_redaction.py:35`, `tests/unit/test_assets.py:39` (plus a password hash in `judgment-day/target-slice1-r1.diff:2769`). Reproduce: `git grep "MigSoc***REDACTED***"`. Decision needed: rotate the password, scrub files, extend `.gitignore` (`openspec/changes/**/apply-progress.md`, `*judgment-day*.diff`), and decide on git-history purge.

**F2 · HIGH · Docker image cannot boot** — `gunicorn` is declared neither in `pyproject.toml` nor in `uv.lock`; `Dockerfile` copies only `app/` and `entrypoint.sh` (not `gunicorn_conf.py`); `gunicorn_conf.py` sets no worker class/bind/workers; base image default CMD is `python3`. Reproduce: `grep gunicorn pyproject.toml uv.lock` (0 matches) + `grep COPY Dockerfile`. Decision needed: intended production invocation (worker class, count, bind).

**F3 · HIGH · RLS defense void if app role owns tables (deployment-dependent)** — migrations enable RLS but never `FORCE ROW LEVEL SECURITY`; `.env.example` runs migrations as `soc360_app`; CI tests run as the table owner. Without FORCE, the owner bypasses every policy and isolation rests on ORM scoping alone. Reproduce: run the `pg_class`/`relowner` query quoted in the security report per environment. Decision needed: separate migration role vs `FORCE ROW LEVEL SECURITY` (or both).

**F4 · HIGH · CI runs no static gates** — `.github/workflows/ci.yml` has no ruff, mypy, secret-scan, or coverage step (0 grep matches), while `README.md` claims "CI runs tests, ruff, mypy, and lockfile freshness checks". Consequence: ruff/mypy have no tool config (`pyproject.toml` has no `[tool.ruff]`/`[tool.mypy]`) and do not run anywhere. Decision needed: add gates to CI or correct the README.

### P1 — fix soon (security/robustness)

**F5 · MEDIUM · `verify_password` explodes on malformed hash** — `app/core/security.py:52`: `bcrypt.checkpw` raises `ValueError: Invalid salt` on any non-bcrypt string instead of returning `False`. Surfaced live by test pollution (60 errors). Reproduce: `bcrypt.checkpw(b"x", b"fakehash")`.

**F6 · MEDIUM · `/tenants/{id}` exposes tenant settings to any member** — `app/modules/tenants/router.py` GET has membership pre-check but no role gate; `TenantResponse.settings` serializes notification email, schedule, thresholds, limits (`schemas.py:66-83`). Reproduce: viewer login → 200 with full settings.

**F7 · MEDIUM · Unauthenticated PostgreSQL catalog probe** — `/health/db/indexes` (`app/main.py`) exposes index names and an unauthenticated DB touch. Reproduce: `curl` without credentials.

**F8 · MEDIUM · Refresh-token rotation lacks reuse detection / family revocation** — `app/modules/auth/service.py:461-505`: replayed revoked token yields plain 401; attacker's rotated session survives. Decision: implement family revocation + `refresh_token_reuse_detected` event.

**F9 · MEDIUM · Rate-limit pre-checks fail open on non-RedisError exceptions** — `app/modules/auth/router.py:117-121` (and `/refresh`, `/logout`, `/change-password`): final `except Exception: continue` silently skips the brute-force guard.

**F10 · MEDIUM · Log redaction is exact-match only** — `app/core/logging.py:7-15`: keys like `access_token` are not redacted; full tracebacks pass through unredacted. Latent trap, no active leak found today.

### P2 — fix in the normal flow

**F11 · MEDIUM · Stale tests / schema drift after the assets rename** — `tests/sdd/test_restore-indexes-concurrently.py` (pre-rename columns `name`/`hostname`, seeds `hashed_password='fakehash'` into the shared test DB without effective cleanup — its own comment acknowledges the pollution); `tests/integration/test_f2_tenant_isolation.py` (5); `tests/unit/test_f2_models.py` (3); `tests/unit/test_assets.py` (4). Local suite: 1221 passed / 16 failed / 60 errors (`pytest -m "not toxiproxy and not redis_pressure"`); `asyncpg UndefinedColumnError: column "value"` on the un-migrated 5432 DB confirms drift in both directions. Also `tests/unit/test_imports.py[app/main.py]`.

**F12 · MEDIUM · Dual-write without outbox** — `app/modules/assets/service.py`: Postgres commit and Redis Streams publish are not atomic (asset persisted but event lost if Redis fails post-commit). Same pattern in `update`/`delete`.

**F13 · MEDIUM · gunicorn defaults unconfigured / root container / no HEALTHCHECK** — `gunicorn_conf.py` only holds the metrics hook (1 worker, 127.0.0.1 defaults); no `USER` in Dockerfile (acknowledged by `tests/sdd/test_uv_migration.py:219`); no image HEALTHCHECK.

**F14 · MEDIUM · Migration hazards** — `70dc591dac68:13-14`: NOT NULL columns without `server_default` (fails on non-empty table); `bfca7016cbb7:186-189`: redundant single-column indexes never dropped (write amplification). Positives: NOT VALID→VALIDATE FK pattern, `CREATE INDEX CONCURRENTLY` in `autocommit_block`, full downgrades everywhere are best-in-class.

**F15 · MEDIUM · README drift** — migration count (7 vs 8), assets status (models-only vs full 989-loc vertical), "removed" modules still on disk empty, API table missing assets endpoints.

### P3 — hygiene backlog

- Unsalted truncated email hashes (`rate_limit.py:39-41`, `pii.py:28-35`) — recommend HMAC + per-tenant salt.
- Raw client IPs in rate-limiter logs vs masked IPs in auth events.
- Inline CI/test credentials (`ci.yml`, seed/test passwords) — migrate to Actions secrets; keep disposable values.
- Loose pins on security-sensitive deps (`PyJWT`, `bcrypt`, `prometheus-client`) — exact-pin auth-critical libs.
- `DATABASE_URL_MIGRATION` is a plain `str`, not `SecretStr` (`config.py:44`).
- `docker-compose.yml` Redis binds all interfaces (dev-only compose); `entrypoint.sh` comment mentions `--forward-allowed-ips` but it is not passed.
- Missing tool config: `[tool.ruff]`, `[tool.mypy]` in `pyproject.toml`; pyright declared via config file only; pytest-cov absent (coverage unknowable).

## Verified positives

- RLS policies on all 7 domain tables + well-designed cross-tenant 403 chokepoint (elevate → compare → restore, `SET LOCAL`).
- JWT HS256-only, alg pinned, DB-authoritative claims; revocation via Redis jti denylist, fail-closed 503s.
- Assets service: centralized tenant predicate, canonicalization, publish-after-commit, defensive duplicate-constraint detection; CSV export streams with its own RLS-scoped session.
- No N+1 loops, no sync-blocking calls, no `print()` in `app/`.
- Excellent migrations for complex operations; `.gitignore` coverage correct; no `.env` present in worktree; strict pytest markers.

## Honest limitations

1. Deployment-dependent findings (F2 worker-class invocation, F3 RLS ownership, TRUSTED_PROXIES) could not be observed live.
2. Local venv lacks dev deps (ruff/mypy unspawnable); pytest-cov absent — per-module coverage not asserted.
3. Secret-guard redacted some credential values at read time; those lines verified non-placeholder by pattern only.
4. No dynamic/fuzz analysis, no git-history mining, no runtime probing (read-only constraint).
5. Out of scope: frontend, Celery wiring, docker-compose.redis-pressure runtime behavior, `app/core/contracts.py`/`types.py` full reads, LLM provider payload builders.
